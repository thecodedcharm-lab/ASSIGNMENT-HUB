# Git Cherry-Pick Assignment

## Q1. Theory: Understanding Cherry-Pick

### 1. What is `git cherry-pick`?

`git cherry-pick` is a Git command used to select a specific commit from another branch and apply its changes to the current branch.

### 2. Difference between Cherry-Pick and Merge

| Cherry-Pick                     | Merge                              |
| ------------------------------- | ---------------------------------- |
| Selects specific commits.       | Combines entire branch changes.    |
| Creates new commit IDs.         | Usually combines branch histories. |
| Used to apply selected changes. | Used to integrate branches.        |

### 3. Does cherry-pick move the original commit?

No, cherry-pick does not move the original commit. The original commit remains in its branch, and a new commit is created in the current branch.

### 4. Why does cherry-pick create a new commit?

Cherry-pick creates a new commit because it applies the selected changes to the current branch with a different parent commit.

### 5. Purpose of Cherry-Pick Commands

* `git cherry-pick --continue`: Continues the cherry-pick process after resolving conflicts.
* `git cherry-pick --abort`: Cancels the cherry-pick process and restores the previous state.
* `git cherry-pick --skip`: Skips the current commit and moves to the next commit in the sequence.

### 6. Difference Between Commit Ranges

**Command 1:**

```bash
git cherry-pick <start_commit>..<end_commit>
```

Cherry-picks commits after the starting commit up to and including the ending commit.

**Command 2:**

```bash
git cherry-pick <start_commit>^..<end_commit>
```

Cherry-picks commits starting from the starting commit up to and including the ending commit.

## Q2. Practical: Cherry-Pick a Specific Commit

### Project: Student Management System

**Step 1: Initialize Repository**

```bash
mkdir Student-Management
cd Student-Management
git init
```

**Step 2: Create Student.txt**

```bash
echo "Student Management System" > Student.txt
```

```bash
git add Student.txt
git commit -m "Create student management system"
```

**Step 3: Create a New Branch**

```bash
git branch student-info
git switch student-info
```

**Step 4: Add Rahul's Information**

```bash
echo "Rahul - Student ID: 101" >> Student.txt
git add Student.txt
git commit -m "Add Rahul student information"
```

**Step 5: Add Amit's Information**

```bash
echo "Amit - Student ID: 102" >> Student.txt
git add Student.txt
git commit -m "Add Amit student information"
```

**Step 6: Switch to Main**

```bash
git switch main
```

**Step 7: Find Amit's Commit ID**

```bash
git log student-info --oneline
```

Copy the commit ID of Amit's commit.

**Step 8: Cherry-Pick Amit's Commit**

```bash
git cherry-pick <amit_commit_id>
```

**Step 9: Check Commit History**

```bash
git log --oneline --graph --all
```

**Expected Result:**

* The original Amit commit remains on `student-info`.
* A new cherry-picked Amit commit appears on `main`.
* Rahul's commit is not included in `main`.

## Q4. Practical: Cherry-Pick Commit Range

### Project: Website Development

**Step 1: Create Repository**

```bash
mkdir Website-Project
cd Website-Project
git init
```

**Step 2: Create Four Commits**

```bash
echo "Homepage" > website.txt
git add website.txt
git commit -m "Create homepage"
```

```bash
echo "Navigation Bar" >> website.txt
git add website.txt
git commit -m "Add navigation bar"
```

```bash
echo "Login Page" >> website.txt
git add website.txt
git commit -m "Add login page"
```

```bash
echo "Login Validation" >> website.txt
git add website.txt
git commit -m "Add login validation"
```

**Step 3: Create a Feature Branch**

```bash
git branch website-feature
```

**Step 4: Find Commit IDs**

```bash
git log --oneline
```

Copy the commit IDs of the second and fourth commits.

**Task 1: Excluding Starting Commit**

```bash
git cherry-pick <second_commit>..<fourth_commit>
```

**Selected Commits:**

* Add login page
* Add login validation

The starting commit is excluded, while the ending commit is included.

**Task 2: Including Starting Commit**

To demonstrate this separately, first reset the test branch to its original state or create another test branch from the initial commit.

```bash
git cherry-pick <second_commit>^..<fourth_commit>
```

**Selected Commits:**

* Add navigation bar
* Add login page
* Add login validation

The starting commit is included because `^` refers to its parent commit.

**Difference:**

| Command       | Selected Commits         |
| ------------- | ------------------------ |
| `start..end`  | Excludes starting commit |
| `start^..end` | Includes starting commit |

## Q5. Practical: Resolve a Cherry-Pick Conflict

### Project: Student Management System

**Step 1: Create Repository**

```bash
mkdir Student-Conflict
cd Student-Conflict
git init
```

**Step 2: Create Student.txt**

```bash
echo "Student Name: Rahul" > Student.txt
git add Student.txt
git commit -m "Create student record"
```

**Step 3: Create Feature Branch**

```bash
git branch feature
git switch feature
```

**Step 4: Modify Student.txt on Feature**

```bash
echo "Student Name: Amit" > Student.txt
git add Student.txt
git commit -m "Update student name to Amit"
```

**Step 5: Find Feature Commit ID**

```bash
git log --oneline
```

Copy the feature commit ID.

**Step 6: Switch to Main**

```bash
git switch main
```

**Step 7: Modify the Same Line on Main**

```bash
echo "Student Name: Priya" > Student.txt
git add Student.txt
git commit -m "Update student name to Priya"
```

**Step 8: Cherry-Pick Feature Commit**

```bash
git cherry-pick <feature_commit_id>
```

A conflict occurs because both branches modified the same line.

**Step 9: Resolve Conflict**

Open `Student.txt` and manually replace the conflict content with:

```text
Student Name: Amit and Priya
```

**Step 10: Stage Resolved File**

```bash
git add Student.txt
```

**Step 11: Continue Cherry-Pick**

```bash
git cherry-pick --continue
```

**Step 12: Check Commit History**

```bash
git log --oneline --graph --all
```

**Result:**

The conflict is resolved successfully, and the cherry-picked changes are committed to the main branch.

## Q6. Short Practical + Theoretical Questions

### 1. Find Commit History

```bash
git log --oneline
```

**Explanation:** Displays commit history in a short format with commit IDs and commit messages.

### 2. Cherry-Pick One Commit

```bash
git cherry-pick <commit_id>
```

**Explanation:** Applies a specific commit from another branch to the current branch.

### 3. Cherry-Pick Multiple Commits

```bash
git cherry-pick <commit_id1> <commit_id2>
```

**Explanation:** Applies multiple selected commits to the current branch in the given order.

### 4. Cherry-Pick a Range

```bash
git cherry-pick <start_commit>..<end_commit>
```

**Explanation:** Applies commits after the starting commit up to and including the ending commit.

### 5. Cherry-Pick a Range Including Starting Commit

```bash
git cherry-pick <start_commit>^..<end_commit>
```

**Explanation:** Applies commits starting from the starting commit up to and including the ending commit.

### 6. Continue After Resolving a Conflict

```bash
git cherry-pick --continue
```

**Explanation:** Continues the cherry-pick process after resolving and staging conflicts.

### 7. Cancel Cherry-Pick

```bash
git cherry-pick --abort
```

**Explanation:** Cancels the ongoing cherry-pick operation and restores the branch to its previous state.

### 8. Skip the Current Commit

```bash
git cherry-pick --skip
```

**Explanation:** Skips the current commit during a cherry-pick sequence and proceeds to the next commit.

## Conclusion

Git Cherry-Pick is useful when we want to apply specific commits from one branch to another without merging the entire branch.

It helps developers select required changes, maintain separate branch histories, and manage conflicts during collaborative development.
