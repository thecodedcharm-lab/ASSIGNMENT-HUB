# Q1. Rebase, Merge & Merge Conflict

### 1. Define Git Merge, Merge Conflict and Git Rebase.

**1. Git Merge**

Git Merge is a command used to combine changes from two different branches into one branch. It helps developers integrate their work without losing commits.

**2. Merge Conflict**

A Merge Conflict occurs when Git cannot automatically combine changes from different branches, usually because two developers have modified the same part of a file.

**3. Git Rebase**

Git Rebase is a Git command that moves or reapplies commits from one branch onto another branch. It creates a cleaner and more linear commit history.

### 2. Explain Merge vs Rebase with a suitable diagram.

**Git Merge:**

Git Merge combines two branches and creates a merge commit when necessary.

```text
       E------F
      /        \
A----B----C-----M  main
```

Here:

* A, B and C are commits on main.
* E and F are commits on another branch.
* M is the merge commit.

**Git Rebase:**

Git Rebase moves the commits of one branch on top of another branch.

Before Rebase:

```text
A---B---C  main
     \
      D---E  product-page
```

After Rebase:

```text
A---B---C  main
         \
          D'---E'  product-page
```

Here, D' and E' are new commits created by reapplying the original changes.

**Difference:**

| Git Merge                                    | Git Rebase                            |
| -------------------------------------------- | ------------------------------------- |
| Combines two branches.                       | Moves commits onto another branch.    |
| May create a merge commit.                   | Does not create a merge commit.       |
| Preserves original branch history.           | Creates a linear history.             |
| Useful for preserving collaboration history. | Useful for maintaining clean history. |

### 3. Write three advantages of Git Rebase.

1. **Clean History:** Maintains a linear and organized commit history.
2. **Easy Tracking:** Makes it easier to understand and track project changes.
3. **Better Collaboration:** Helps developers update their branches with the latest changes from the main branch.

### 4. Explain why Rebase is useful in real-life projects.

Git Rebase is useful in real-life projects because multiple developers work on different branches simultaneously.

When developers make changes to their branches, the main branch may also receive new updates.

Using Rebase, developers can update their feature branches with the latest changes from the main branch.

It helps to:

* Maintain clean commit history.
* Avoid unnecessary merge commits.
* Make code reviews easier.
* Keep feature branches updated.
* Improve team collaboration.

### 5. Explain the purpose of the following commands.

**1. git rebase --continue**

This command continues the rebase process after resolving a merge conflict and staging the resolved files.

```bash
git add .
git rebase --continue
```

**2. git rebase --abort**

This command cancels the ongoing rebase process and restores the branch to its original state before the rebase started.

```bash
git rebase --abort
```

**3. git rebase --skip**

This command skips the current commit that is causing the conflict and continues the remaining rebase process.

```bash
git rebase --skip
```

# Q2. Merge and Rebase

## Scenario: E-Commerce Website

### Step 1. Create a project and initialize Git.

```bash
mkdir ecommerce-website
cd ecommerce-website

git init
git branch -M main
```

Create the initial file:

```bash
echo "E-Commerce Website" > index.html
```

Add and commit:

```bash
git add .
git commit -m "Initial commit: Create ecommerce website"
```

Save the initial commit as a reference:

```bash
git tag initial-state
```

```bash
git switch -c product-page
```

**First commit:**

```bash
echo "Product Listing Section" > product.html

git add .
git commit -m "Create product listing page"
```

**Second commit:**

```bash
echo "Product Details and Price" >> product.html

git add .
git commit -m "Add product details and pricing"
```

### Step 3. Switch to main and make two commits.

```bash
git switch main
```

**First commit:**

```bash
echo "Website Navigation Bar" > navbar.html

git add .
git commit -m "Add website navigation bar"
```

**Second commit:**

```bash
echo "Website Footer Section" > footer.html

git add .
git commit -m "Add website footer section"
```

### Step 4. Display commit history before merge.

```bash
git log --oneline --graph --all
```

**Expected commit structure:**

```text

```

The actual order and commit IDs will be displayed by Git.

### Step 5. Merge product-page into main.

```bash
git switch main

git merge product-page
```

If Git reports that a fast-forward merge is possible, it may simply move the main branch forward without creating a merge commit.

### Step 6. Display history after merge.

```bash

```

Now switch to the product branch:

### Step 8. Display history after Rebase.


**Expected structure:**

```text
* Add product details and pricing

```

### Step 9. Write two differences observed between Merge and Rebase.

**1. Commit History**

* Merge preserves the original branching history and may create a separate merge commit.
* Rebase creates a linear commit history by placing feature commits after the latest main commits.

**2. Commit IDs**

* Merge generally preserves the original commits.
* Rebase creates new commit IDs because commits are reapplied onto a different base.

# Q3. Rebase Conflict

## Scenario: Student Management System

### Step 1. Create a project and initialize Git.

```bash
mkdir student-management
cd student-management

git init
git branch -M main
```

Create a file:

```bash
echo "Student Name: Unknown" > student.txt
```

Commit:

```bash
git add .
git commit -m "Initial commit: Create student management system"
```

### Step 2. Create student-profile branch.

```bash
git switch -c student-profile
```

### Step 3. Make two commits on student-profile.

**First commit:**

```bash
echo "Student Email: student@gmail.com" >> student.txt

git add .
git commit -m "Add student email information"
```

**Second commit:**

```bash
echo "Student Course: Computer Science" >> student.txt

git add .
git commit -m "Add student course information"
```

### Step 4. Switch to main and modify the same line.

```bash
git switch main
```

Modify the first line of student.txt:

```bash
echo "Student Name: Rahul" > student.txt
```

Commit:

```bash
git add .
git commit -m "Update student name on main branch"
```

### Step 5. Switch back to student-profile.

```bash
git switch student-profile
```

### Step 6. Perform Rebase.

```bash
git rebase main
```

Git will show a merge conflict because the same line has been modified on both branches.

### Step 7. Resolve the merge conflict.

Open `student.txt` in VS Code.

You may see:

```text
<<<<<<< HEAD
Student Name: Rahul
=======
Student Name: Unknown
>>>>>>> commit-id
```

Resolve the conflict by keeping the required content:

```text
Student Name: Rahul
Student Email: student@gmail.com
```

Save the file.

### Step 8. Complete the Rebase.

```bash
git add .

git rebase --continue
```

If another conflict occurs, resolve it in the same way and repeat the commands.

After successful rebase, check the file:

```bash
cat student.txt
```

### Step 9. Demonstrate git rebase --abort.

Create another conflict scenario.

First, switch to main:

```bash
git switch main
```

Create a new branch:

```bash
git switch -c student-address
```

Modify the student name:

```bash
echo "Student Name: Amit" > student.txt

git add .
git commit -m "Change student name to Amit"
```

Switch to main:

```bash
git switch main
```

Make a conflicting change:

```bash
echo "Student Name: Priya" > student.txt

git add .
git commit -m "Change student name to Priya"
```

Switch back:

```bash
git switch student-address
```

Start Rebase:

```bash
git rebase main
```

Git will report a conflict.

Now abort the rebase:

```bash
git rebase --abort
```

**Explanation:**

The `git rebase --abort` command cancels the ongoing rebase process.

After aborting:

* The rebase process stops.
* The branch returns to its original state before rebase.
* The original commits on student-address remain unchanged.
* The changes from main are not applied to student-address through this rebase.

### Step 10. Demonstrate git rebase --skip.

Create another branch:

```bash
git switch main

git switch -c student-course
```

Make a commit:

```bash
echo "Student Course: BCA" >> student.txt

git add .
git commit -m "Add BCA course information"
```

Switch to main:

```bash
git switch main
```

Add the same course information:

```bash
echo "Student Course: BCA" >> student.txt

git add .
git commit -m "Add BCA course on main branch"
```

Switch back:

```bash
git switch student-course
```

Start Rebase:

```bash
git rebase main
```

Git may report a conflict because the same change has already been applied on main.

Skip the current commit:

```bash
git rebase --skip
```

**Explanation:**

The `git rebase --skip` command skips the current commit that is being replayed during the rebase.

In this scenario, it skips:

`Add BCA course information`

The BCA course information already exists in the main branch, so the feature branch does not need to apply the same change again.

**Note:** Git may automatically recognize an already-applied commit and skip it without requiring manual conflict resolution. If that happens, the rebase may finish automatically.

### Step 11. Display final commit history.

Run:

```bash
git log --oneline --graph --all
```
