# Assignment A - My First Stash

## Task A1 - Basic Stash

### Setup

```bash
git clone <repo-url>
cd git-stash-A-<username>

echo "# Stash Practice" > README.md

git add README.md
git commit -m "Initial commit"
git push -u origin main
```

### Step 1: Create modified and untracked files

```bash
echo "Learning Git Stash" >> README.md

echo "My personal notes" > notes.txt
```

### Step 2: Stash tracked changes

```bash
git stash
```

### Step 3: Stash untracked files

```bash
git stash -u
```

### Step 4: Display stash list

```bash
git stash list
```

### Answers

**Q1: How many stashes do you see? Which is latest?**

I can see 2 stashes in the stash list. The latest stash is `stash@{0}`, while the previous stash is `stash@{1}`.

**Q2: Which stash has notes.txt? How do you know?**

`stash@{0}` contains `notes.txt` because I used `git stash -u`, which includes untracked files. I can verify it using `git stash show --include-untracked stash@{0}`.

### Step 5: Restore changes

```bash
git stash pop
git stash list
```

**Q3: What happened to the stash list after pop?**

The latest stash was applied to my working directory and removed from the stash list. The previous stash remains in the list.

## Task A2 - Switch Branch with Half-Done Work

### Step 1: Create a new branch

```bash
git switch -c feature/login
```

### Step 2: Create login.html and commit it

```bash
echo "<h1>Login Page</h1>" > login.html

```

```bash

```


```bash
git stash -u -m "WIP: login page"
```

```bash

```

```bash

```

### Step 8: Restore login work

```bash

git stash pop
```

**Q4: Why did you need git stash before switching to main?**

I used Git Stash to temporarily save my unfinished work before switching branches. It allowed me to switch to main without losing my staged, unstaged and untracked changes.

After successfully applying and removing the stash using `git stash pop`, zero stashes remain if there were no older stashes.

# Assignment B - Stash Concepts

## Q1. What is git stash in simple words? When do we use it?

Git Stash is a command used to temporarily save unfinished changes without committing them. It helps developers switch branches or work on urgent tasks without losing their current work.

## Q2. Which files are stashed by different commands?

Given:

* app.js (tracked, modified)
* test.js (untracked)
* .env (ignored)

**git stash**

Stashes only `app.js` because it is a tracked modified file.

**git stash -u**

Stashes `app.js` and `test.js` because `-u` includes untracked files.

**git stash -a**

Stashes all three files because `-a` includes tracked, untracked and ignored files.

## Q3. Explain the difference between git stash apply and git stash pop.

**git stash apply:**

Restores stashed changes but keeps the stash in the stash list.

**git stash pop:**

Restores stashed changes and removes the stash from the stash list if the operation succeeds.

## Q4. When would you prefer apply over pop? Give one example.

I prefer `git stash apply` when I want to restore changes but keep a backup in the stash list.

Example: When testing the same changes on multiple branches, I can apply the stash repeatedly without removing it.

## Q5. What do these commands do?

**git stash drop:**

Removes a specific stash from the stash list.

```bash
git stash drop stash@{0}
```

**git stash clear:**

Removes all stashes from the stash list.

```bash
git stash clear
```

## Q6. Which is the latest stash?

Given:

```text
stash@{0}: WIP on feature/login: ...
stash@{1}: WIP on main: ...
```

The latest stash is `stash@{0}` because Git stores the newest stash at index 0.

If we run `git stash pop`, Git applies and removes `stash@{0}` if the operation succeeds.

## Q7. Why is it good to use meaningful stash messages?

Meaningful stash messages help developers identify the purpose of each saved change. They make stash management easier and prevent confusion when multiple unfinished tasks are saved.

Example:

```bash
git stash push -m "WIP: login form"
```

## Q8. Write the exact commands to stash work safely.

Given:

* checkout.html is committed.
* checkout.css is staged.
* checkout.js is untracked.

Commands:

```bash
git stash -u -m "WIP: checkout page"

git switch main
```

The `-u` option includes untracked files along with tracked changes. The committed file remains safely committed in the branch.


Using `-m` allows us to add a meaningful description to a stash. It makes it easier to identify and manage different stashes, especially when working on multiple tasks.
