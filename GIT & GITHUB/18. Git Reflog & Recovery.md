# Git Reflog & Recovery Assignment

## PART 1: Recovery After `git reset --hard`

### 1. Create Repository

```bash
mkdir reflog-practice-part1
cd reflog-practice-part1

git init
```

### 2. Create C0

```bash
echo "# Git Reflog Practice" > README.md

git add README.md
git commit -m "C0: Added project README"
```

Save C0 commit hash:

```bash
git log --oneline
```

### 3. Create C1

```bash
echo "<h1>Welcome</h1>" > index.html

git add index.html
git commit -m "C1: Added welcome HTML page"
```

### 4. Create C2

```bash
echo "body { background-color: lightblue; }" > style.css

git add style.css
git commit -m "C2: Added basic CSS styling"
```

### 5. Check Initial History

```bash
git log --oneline
```

Take screenshot.

### 6. Reset to C0

Replace `<C0-HASH>` with your actual C0 commit hash.

```bash
git reset --hard <C0-HASH>
```

Check history:

```bash
git log --oneline
```

Take screenshot.

### 7. Find Lost Commits

```bash
git reflog
```

Find the hash of C2.

### 8. Recover Lost Commits

```bash
git switch --detach <C2-HASH>
```

Create a recovery branch:

```bash
git switch -c recovery/restore-work
```

Return to main:

```bash
git switch main
```

Merge recovered work:

```bash
git merge recovery/restore-work
```

### 9. Verify Recovery

```bash
git log --oneline --graph --all
```

Check files:

```bash
ls
```

All three files should be present:

* README.md
* index.html
* style.css

### 10. Push to GitHub

Create an empty GitHub repository named `reflog-practice-part1`.

```bash
git remote add origin https://github.com/YOUR-USERNAME/reflog-practice-part1.git

git push -u origin main
git push origin recovery/restore-work
```

### 1. Run Reflog

Run this command in either repository:

```bash

```

### 2. Written Explanation

Add the following explanation to your notebook or README.

```markdown
# Part 3: Reflog Exploration

## What is Git Reflog?

Git Reflog is a command that records changes in the HEAD position of a repository. It helps us find previous commits and recover lost work.

## Reflog Analysis

1. HEAD@{0}: git merge rework/readme-update
   - The rework branch was merged into the main branch.

2. HEAD@{1}: git switch main
   - Switched from the rework branch to the main branch.

3. HEAD@{2}: git commit -m "C3: Updated README"
   - Created a new commit containing the README description.

4. HEAD@{3}: git switch -c rework/readme-update <C0-HASH>
   - Created and switched to a new branch starting from C0.

5. HEAD@{4}: git commit -m "C2: Added helper functions"
   - Created a commit containing helper functions in utils.js.

## Conclusion

Git Reflog maintains a record of previous HEAD movements. It helps recover lost commits and track changes made in a Git repository.
```

**Note:** HEAD@{0}, HEAD@{1}, etc. are dynamic. Their exact order depends on your actual reflog output. Match the explanations with your terminal entries.
