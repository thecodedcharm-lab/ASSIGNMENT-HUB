# A. One-Line Answer Questions

**1. What is the first step you must take to contribute to a repository if you are not added as a collaborator?**

Answer: Fork the original repository into your GitHub account.

**2. Which GitHub button creates a personal copy of a repository under your account?**

Answer: The Fork button.

**3. Why should you never work directly on the `main` branch?**

Answer: To keep the main branch safe and avoid unwanted changes.

**4. What is the purpose of creating a Pull Request?**

Answer: To request the owner to review and merge our changes into the original repository.

**5. Who reviews and merges the Pull Request in this collaboration model?**

Answer: The repository owner or team leader.

# D. Descriptive Answer Questions

### 1. Explain the difference between being added as a collaborator and using the Fork + Pull Request method.

**Answer:**

* **Collaborator:** A collaborator gets permission to directly access and make changes to the original repository.
* **Fork + Pull Request:** A contributor creates their own copy of the repository, makes changes and submits a Pull Request for review.

The main difference is that collaborators have direct access, while fork contributors work independently.

### 2. Why is the Fork + Pull Request method considered safer for the main repository?

**Answer:**

The Fork + Pull Request method is safer because contributors work on their own copies of the repository. Their changes do not directly affect the original project. The owner reviews the Pull Request before merging changes.

### 3. Describe the complete step-by-step process a student should follow to contribute a small feature using the open-source style collaboration method.

**Answer:**

1. **Fork:** Open the original GitHub repository and click the Fork button.
2. **Clone:** Clone the forked repository to the local computer.
3. **Create Branch:** Create a new feature branch using `git switch -c feature/page-name`.
4. **Code:** Make the required changes using HTML and CSS.
5. **Add Changes:** Use `git add .` to stage the changes.
6. **Commit:** Use `git commit -m "Added new page"` to save the changes.
7. **Push:** Use `git push origin feature/page-name` to upload the branch.
8. **Pull Request:** Open GitHub and create a Pull Request from the feature branch.
9. **Review:** The repository owner reviews the changes.
10. **Merge:** After approval, the owner merges the Pull Request into the main repository.

**Conclusion:** This method allows multiple people to contribute safely without needing direct collaborator access.
